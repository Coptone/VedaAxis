# 已确认决策

| 决策 | 结论 |
| --- | --- |
| 交付方式 | 分阶段实现完整 MVP，阻断 PoC 优先。 |
| 热键栏高亮 | 接受贴合原生槽位的覆盖层，不自动施法。 |
| Dalamud 版本 | 以最新同步版本为目标。 |
| 轨道模式 | 同时支持四轨与八轨。 |
| 账户与分享 | 邮箱密码、插件一次性绑定码、JWT、匿名只读分享。 |
| DMU 种子 | 允许引用 Ikuya/Mitty 与 LPDU，必须保留来源和未验证状态。 |
| 许可证 | 不添加许可证。 |
| 首版战斗触发 | 已加载有效本地计划且 Territory 匹配时，以 `InCombat` 进入作为自动开始；脱战、团灭/重开和副本完成自动结束。手动开始/停止仅作为调试兜底。 |
| 倒计时触发 | 不进入首版；在自动开怪主路径稳定后再设计用户倒计时来源、取消与重复触发规则。 |
| 在线部署顺序 | 先完成本地 Web/API/PostgreSQL/插件最小数据闭环，再部署 HTTPS 测试环境并完成真实网络验收，最后才进入生产部署。 |
| 首版服务组成 | 测试环境先部署 Web、API 与 PostgreSQL；当前没有实际服务端用例的 Redis 不作为首版阻断项，也不先建设独立运营后台。 |
| 首个自动生命周期实机样本 | 使用 O8S（Territory 755）H2/八轨计划，降低 DMU 八人进本门槛；该样本只验证插件生命周期和数据闭环，不作为 DMU Action ID、阶段时间或锚点证据。 |
| 外部时间轴导入 | 首版允许用户按需导入受支持的 M-Spec URL，只形成带来源的 `POC_PENDING` 候选；不得定时整站镜像、不得保留玩家/报告身份，也不得自动保存或发布。 |
| 阶段时间语义 | P1/P2/P4/P5 使用 `ABSOLUTE`：阶段完整时间固定；P3 使用 `RELATIVE`：阶段内机制间隔固定，但阶段可随击杀提前结束。首个默认内容只交付 P1/P2。 |
| P1/P2 默认计划 | 附件 `p1-2.xlsx` 转为 DMU 八轨公共默认计划；Excel 显示值按“分:秒”解释，来源保持 `POC_PENDING`，不得因自动规则通过而提升为 `VERIFIED`。 |
| 单体目标高亮 | 任务通过 `targetTrackId` 指向 MT/ST 等轨道；插件按职业唯一匹配队友，不依赖每个人的队伍列表顺序。无匹配或重复职业时，允许开打前手动指定；映射仅驻留本次插件进程，不保存角色名。 |
| 机制伤害展示 | 左侧时间轴同时显示 AOE/平 A/死刑/机制伤害、物理/魔法/特殊/未知属性和校准状态；没有可追溯数值时必须显示待校准，不能填猜测值。 |
| 减伤效果口径 | 以固定游戏数据版本的人工复核效果目录为准；乘区、不叠加组、目标、范围和持续时间必须进入计算。治疗威力护盾、无敌和条件触发在输入不足时只能列为未计入或人工特判。 |
| FFLogs 伤害值 | FFLogs 单份报告只生成匿名 `POC_PENDING` 校准候选。实战 `amount` 和日志 `unmitigatedAmount` 均不得直接作为跨装备/跨队伍固定伤害；发布数值前必须完成人工映射与多样本或公式复核。 |
| 生存结论 | 首版输出“已建模部分可存活/不足/需特判”，不输出跨队伍的“100% 保证”；没有机制伤害校准、目标/范围确认或治疗属性等必要输入时拒绝给出完整数值结论。 |
