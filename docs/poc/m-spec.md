# M-Spec 时间轴导入 PoC

## 目标与边界

M-Spec 只作为用户主动提供 URL 时的外部参考来源。VedaAxis 不定时抓取整站、不原样再分发公开排名数据，也不把候选直接变成活动计划。所有导入结果都保留来源并标记为 `POC_PENDING`，必须在管理端预览后明确应用，之后仍需另行保存或发布。

服务端只接受 `https://raalm.com/m-spec/timelinev2.html` 的已知 `boss` 与合法 `spec` 参数，并根据内置映射构造固定数据路径；HTTP 客户端拒绝重定向，具有连接/请求超时和响应大小上限。任意主机、端口、用户信息、未知 Boss 或非法 slug 会在请求上游前被拒绝。

## 2026-08-05 观察样本

参考页面：`https://raalm.com/m-spec/timelinev2.html?boss=dancing-mad&spec=sage-sage&buddy=0`

- Boss 数据 `dancing_mad.json`：204 条记录，包括 4 个阶段、30 个坦克死刑、59 个全体伤害和 111 个普通机制；200 条包含中文名称。
- Boss 数据没有可用 Action ID，也没有可直接映射到 FFLogs/插件锚点的阶段序号。
- 页面种子阶段起点为 0、120、300、540 秒；检查到的排名样本战斗包含 5 个阶段，起点约为 0、209、429、725、889 秒。两者语义明显不同，不能把样本阶段绝对时间直接覆盖到 Boss 种子。
- Sage 技能目录包含 `RAID_MIT` 与 `SINGLE_MIT` 分类；公开排名样本包含报告、战斗、角色和施法序列。

上述计数是 2026-08-05 的动态观察，不作为站点长期稳定契约。`robots.txt` 允许搜索/引用但声明 `ai-train=no`；未发现明确的可再分发许可证。因此当前实现坚持按需参考、来源署名、最小派生和不提交原始数据。

## 匿名化算法

1. 只读取与请求 `spec` 完全匹配的玩家施法。
2. 只保留技能目录中 `RAID_MIT`、`SINGLE_MIT` 的技能。
3. 每场战斗按自身阶段起点计算施法的阶段相对时间，并按技能、阶段、阶段内发生序号分组。
4. 样本数至少 5 才返回窗口；候选只包含样本数、中位数、P25 和 P75。
5. 报告 ID、角色名、`source_id` 等身份字段不进入响应、计划快照、日志产物或仓库。

## 应用规则

- 管理端先展示阶段数、机制数、Action ID 数、匿名窗口数和全部警告。
- 用户明确点击“应用候选”后才替换本地草稿的阶段/机制。
- 因外部机制 ID 与旧任务不同，应用时清空旧锚点和旧任务，并提前显示清理数量。
- 不改变 4/8 轨模式和轨道绑定；不自动保存、不自动发布。
- Action ID 缺失时不生成伪锚点。后续必须结合 FFLogs 和插件事件补齐/验证，才能提升置信状态。
